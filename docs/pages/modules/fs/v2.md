# fs::v2

Filesystem primitives and typed JSON configuration, second generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["fs-v2"] }
```

`fs-v2` has **no inter-module dependencies** (unlike `fs-v1`, which requires `types` and `color`).

When `fs-v2` is enabled, its public items are re-exported at `musutils::fs::*`; the configuration API lives under `musutils::fs::config::*`.

```rust
use musutils::fs::{copy, copy_dir_all, create_dir_all, new_dir, write, write_atomic};
use musutils::fs::config::{Config, ConfigError, get, rewrite};
```

## Purpose

`fs::v2` reworks [`fs::v1`](v1.md) around explicit `Result`s and typed errors. It provides:

- primitives that mirror `std::fs` more predictably (`copy`, `copy_dir_all`, `create_dir_all`, `remove_dir_all`, `write`, `write_bytes`),
- an **atomic** write (`write_atomic`) that writes to a temporary file and renames it into place,
- path helpers `expand` (tilde + relative-to-cwd + normalize) and `normalize` (correct `..` handling),
- aliases keeping the v1 names (`new_dir`, `current_dir`, `get_curr_dir`, `exists`, `is_exist`, `normalize_path`, `tilda_desir`),
- a typed configuration API: `Config` with `get` / `get_as` / `get_or` / `set` / `save` / `save_to`, `load` / `load_path` / `load_or_create`, and `ConfigError`.

## Filesystem primitives

### `copy`

```rust
pub fn copy<P: AsRef<Path>, Q: AsRef<Path>>(from: P, to: Q) -> io::Result<u64>
```

Thin wrapper over `std::fs::copy`. Returns the number of bytes copied. Overwrites the destination if the OS allows it; does **not** create missing parent directories.

```rust
use musutils::fs::copy;

let n = copy("a.txt", "b.txt")?;
assert_eq!(n, 5);
```

### `copy_dir_all`

```rust
pub fn copy_dir_all<P: AsRef<Path>, Q: AsRef<Path>>(from: P, to: Q) -> io::Result<()>
```

Recursively copies `from` into `to`, creating `to` and its parents. Directories are recreated with `create_dir_all`, files are copied with `std::fs::copy`. Symlinks are followed (the `file_type()` of an entry describes the target).

```rust
use musutils::fs::copy_dir_all;

copy_dir_all("src_tree", "dst_tree")?;
```

### `create_dir_all`

```rust
pub fn create_dir_all<P: AsRef<Path>>(path: P) -> io::Result<()>
```

Thin wrapper over `std::fs::create_dir_all`. Returns an error (does not panic) if the path cannot be created, e.g. when a component is an existing regular file.

```rust
use musutils::fs::create_dir_all;

create_dir_all("/tmp/musutils-demo/a/b/c")?;
```

### `new_dir`

```rust
pub fn new_dir<P: AsRef<Path>>(path: P) -> bool
```

Convenience variant of `create_dir_all` that returns `true` on success and `false` on failure — **no panic, no error value**. Use `create_dir_all` if you need the underlying `io::Error`.

```rust
use musutils::fs::new_dir;

assert!(new_dir("/tmp/musutils-demo/dir"));
assert!(!new_dir("/proc/musutils-cannot-write-here")); // usually fails
```

### `remove_dir_all`

```rust
pub fn remove_dir_all<P: AsRef<Path>>(path: P) -> io::Result<()>
```

Thin wrapper over `std::fs::remove_dir_all`. Removes the directory and everything inside it. Errors if `path` does not exist or is not a directory.

```rust
use musutils::fs::remove_dir_all;

remove_dir_all("/tmp/musutils-demo")?;
```

### `current_dir`

```rust
pub fn current_dir() -> io::Result<PathBuf>
```

Returns `std::env::current_dir()` as a `Result`. Prefer this over `get_curr_dir` if the current directory may have been removed.

```rust
use musutils::fs::current_dir;

let cwd = current_dir()?;
```

### `get_curr_dir`

```rust
pub fn get_curr_dir() -> PathBuf
```

Alias for v1 behavior: calls `current_dir().expect("Failed to get current working directory")`. **Panics** when the current directory cannot be obtained.

```rust
use musutils::fs::get_curr_dir;

let cwd = get_curr_dir();
```

### `exists`

```rust
pub fn exists<P: AsRef<Path>>(path: P) -> bool
```

Thin wrapper over `Path::exists()`. Note the same caveats as `std`:

- Returns `false` for a path the user has no permission to `stat` — not an error.
- Follows symlinks.

```rust
use musutils::fs::exists;

assert!(exists("/tmp"));
assert!(!exists("/tmp/musutils-does-not-exist-xyz"));
```

### `is_exist`

```rust
pub fn is_exist<P: AsRef<Path>>(path: P) -> bool
```

Alias for [`exists`](#exists), kept for source compatibility with v1.

## Path helpers

### `expand`

```rust
pub fn expand<P: AsRef<Path>>(path: P) -> PathBuf
```

The v2 equivalent of v1's `tilda_desir`:

- A leading `~` is replaced with the user's home directory (`home::home_dir()`).
- A relative path (not starting with `~`) is joined with the current directory, or returned as-is if the current directory cannot be obtained.
- An absolute path is returned as-is.
- The result is passed through [`normalize`](#normalize).

```rust
use std::path::PathBuf;
use musutils::fs::expand;

assert_eq!(expand("/tmp/x"), PathBuf::from("/tmp/x"));
```

Unlike v1's `tilda_desir`, `expand` does **not** panic if `current_dir` fails — it returns the relative path unchanged (normalized).

### `tilda_desir`

```rust
pub fn tilda_desir<P: AsRef<Path>>(path: P) -> PathBuf
```

Alias for [`expand`](#expand), kept for source compatibility with v1.

### `normalize`

```rust
pub fn normalize(path: &Path) -> PathBuf
```

Lexically normalizes a path, resolving `.` and `..` components where possible:

- `CurDir` (`.`) is dropped.
- `ParentDir` (`..`) pops the previous component **only if** that component is a `Normal` component.
- If the previous component is `RootDir` (`/`) or a `Prefix` (Windows), the `..` is dropped (you cannot go above the filesystem root).
- If there is no previous component, or it is itself a `..`, the `..` is kept.

```rust
use std::path::{Path, PathBuf};
use musutils::fs::normalize;

assert_eq!(normalize(Path::new("a/./b/../c")), PathBuf::from("a/c"));
assert_eq!(normalize(Path::new("/..")), PathBuf::from("/"));
assert_eq!(normalize(Path::new("a/../../b")), PathBuf::from("../b"));
assert_eq!(normalize(Path::new("")), PathBuf::new());
assert_eq!(normalize(Path::new(".")), PathBuf::new());
```

This is the main behavioral difference from [`fs::v1::normalize_path`](v1.md#normalize_path): v1 always drops `..` by popping, which turns `/..` into an empty path; v2 stops at the root and preserves unresolved `..` prefixes.

`normalize` is purely lexical — it does not access the filesystem, resolve symlinks, or check existence.

### `normalize_path`

```rust
pub fn normalize_path(path: &Path) -> PathBuf
```

Alias for [`normalize`](#normalize), kept for source compatibility with v1.

## Writing

### `write`

```rust
pub fn write<P: AsRef<Path>, C: AsRef<[u8]>>(path: P, content: C) -> io::Result<()>
```

Writes `content` to `path`, creating missing parent directories first.

- `path` accepts `AsRef<Path>` (v1 required `PathBuf`).
- Parent directories are created with `std::fs::create_dir_all` — errors propagate as `io::Error`, no panic.
- The file is opened with `std::fs::write`, so it is truncated if it exists.
- No tilde expansion.

```rust
use musutils::fs::write;

write("a/b/c.txt", b"payload")?;
```

### `write_atomic`

```rust
pub fn write_atomic<P: AsRef<Path>, C: AsRef<[u8]>>(path: P, content: C) -> io::Result<()>
```

Writes `content` to `path` atomically on supported platforms:

1. Parent directories are created with `std::fs::create_dir_all`.
2. A temporary file `.<name>.tmp-<pid>` is created next to `path`.
3. The content is written and flushed with `sync_all`.
4. `std::fs::rename` moves the temporary file onto `path`.

If `path` has no file name (e.g. it ends with `/` or is `/`), the function returns `ErrorKind::InvalidInput` without touching anything.

If the rename fails, the temporary file is removed before returning the error, so no `.<name>.tmp-*` files are left behind on failure paths.

```rust
use musutils::fs::write_atomic;

write_atomic("config.json", b"{\"k\":1}")?;
```

**Notes:**

- Atomicity is per-file. Writing from multiple processes to the same path uses the process ID to separate temporary files, but there is no locking.
- On Windows, `std::fs::rename` fails if the destination exists. In that case `write_atomic` returns the error after removing the temporary file — it does not fall back to `copy`/`remove`.

### `write_bytes`

```rust
pub fn write_bytes<P: AsRef<Path>, C: AsRef<[u8]>>(path: P, contents: C) -> io::Result<()>
```

Alias for [`write`](#write) in v2. (In v1, `write_bytes` was a thin wrapper over `std::fs::write` without creating parents; the v2 version does create them.)

## Configuration (`fs::config`)

The `fs::config` submodule is a typed JSON-configuration layer. Files are stored under:

- Linux and macOS: `~/.config/<app_name>/<file_name>`
- Windows: `~/AppData/Roaming/<app_name>/<file_name>`
- Other platforms: `.` (falls back to the current directory)

The path is computed by [`config_path`](#config_path); it is not exposed as a hard-coded constant.

```rust
use musutils::fs::config::{Config, ConfigError};
use serde_json::json;
```

### `Config`

```rust
pub struct Config {
    // private fields
}
```

A loaded (or in-memory) configuration object. All mutation goes through the methods below. `Config` does **not** implement `Debug` or `Clone` — construct a new value with `from_value` if you need a copy.

#### `Config::from_value`

```rust
pub fn from_value(value: Value) -> Self
```

Builds a `Config` with an empty internal path. `save()` on such a value returns `ConfigError::Io`; use `save_to(path)` instead, or `load_path` / `load_or_create` to obtain a `Config` that remembers its file.

```rust
let mut cfg = Config::from_value(json!({}));
cfg.set("a.b", json!(1)).unwrap();
cfg.save_to("out.json").unwrap();
```

#### `Config::path`

```rust
pub fn path(&self) -> &Path
```

Returns the file path the config was loaded from. Empty for `from_value`.

#### `Config::as_value`

```rust
pub fn as_value(&self) -> &Value
```

Returns the underlying `serde_json::Value`.

#### `Config::get`

```rust
pub fn get(&self, key_path: &str) -> Option<&Value>
```

Looks up a nested value by a dot-separated key path (`"a.b.c"`). Returns `None` if:

- any segment is empty (`""`, `"a..b"`, `".a"`, `"a."`),
- an intermediate value is not an object,
- the final key is missing.

No allocation happens on a successful lookup — the returned reference points into the stored `Value`.

```rust
let cfg = Config::from_value(json!({"a": {"b": {"c": 42}}}));
assert_eq!(cfg.get("a.b.c"), Some(&json!(42)));
assert_eq!(cfg.get("a.x"), None);
```

#### `Config::get_as`

```rust
pub fn get_as<T: DeserializeOwned>(&self, key_path: &str) -> Result<T, ConfigError>
```

Convenience: `get` + `serde_json::from_value`. Returns:

- `ConfigError::KeyNotFound(key_path)` if `get` returns `None`,
- `ConfigError::TypeMismatch { key, expected }` if deserialization fails.

```rust
let cfg = Config::from_value(json!({"a": 42}));
assert_eq!(cfg.get_as::<i32>("a").unwrap(), 42);
assert!(cfg.get_as::<String>("a").is_err());
```

#### `Config::get_or`

```rust
pub fn get_or<T: DeserializeOwned>(&self, key_path: &str, default: T) -> T
```

`get_as(key_path).unwrap_or(default)`. Both "missing" and "wrong type" yield `default`.

#### `Config::set`

```rust
pub fn set(&mut self, key_path: &str, new_value: Value) -> Result<(), ConfigError>
```

Writes `new_value` at `key_path`.

- An empty `key_path` or a key path with empty segments yields `ConfigError::InvalidKeyPath`.
- If the root value is not an object, it is **replaced** with an empty object first.
- For each intermediate segment, if the existing value is a non-object, `set` returns `ConfigError::InvalidKeyPath` — it does **not** silently overwrite. To replace such a value, first `set` it to an object, or start from a fresh object.
- If an intermediate segment does not exist, an empty object is created and traversal continues.

```rust
let mut cfg = Config::from_value(json!({}));
cfg.set("a.b.c", json!(1)).unwrap();
assert_eq!(cfg.get("a.b.c"), Some(&json!(1)));

// Overwriting a scalar with a subtree is rejected:
let mut cfg = Config::from_value(json!({"a": 5}));
assert!(cfg.set("a.b", json!(1)).is_err());
```

#### `Config::save`

```rust
pub fn save(&self) -> Result<(), ConfigError>
```

Serializes the config with `serde_json::to_string_pretty` and writes it to the remembered path using `write_atomic`.

Returns `ConfigError::Io(ErrorKind::InvalidInput)` when the config has no path (`from_value` only). Use `save_to` to write somewhere else.

#### `Config::save_to`

```rust
pub fn save_to<P: AsRef<Path>>(&self, path: P) -> Result<(), ConfigError>
```

Same as `save`, but writes to `path`. Does **not** update the remembered path — subsequent `save()` calls still use the original path.

#### `Config::load`

```rust
pub fn load(app_name: &str, file_name: &str) -> Result<Self, ConfigError>
```

Loads `<config_dir>/<app_name>/<file_name>`. The path is computed by `config_path`.

#### `Config::load_path`

```rust
pub fn load_path<P: AsRef<Path>>(path: P) -> Result<Self, ConfigError>
```

Reads `path`, parses it as JSON and stores the path for later `save()` calls.

Returns `ConfigError::Io` if the file cannot be read and `ConfigError::Parse` if the contents are not valid JSON.

#### `Config::load_or_create`

```rust
pub fn load_or_create(app_name: &str, file_name: &str, default: &str) -> Result<Self, ConfigError>
```

If the file at `config_path(app_name, file_name)` exists, it is loaded. Otherwise:

1. `default` is parsed as JSON **first** — invalid JSON yields `ConfigError::Parse` before any file is created.
2. Missing parents are created with `std::fs::create_dir_all`.
3. The default text is written with `write_atomic` (not pretty-printed — the raw string is written).
4. A `Config` with the parsed value and the file path is returned.

```rust
let cfg = Config::load_or_create("myapp", "conf.json", r#"{"x":1}"#)?;
assert_eq!(cfg.get_as::<i32>("x")?, 1);
```

### Paths

#### `config_dir`

```rust
pub fn config_dir(app_name: &str) -> PathBuf
```

Returns the per-application config directory:

- Linux / macOS: `~/.config/<app_name>`
- Windows: `~/AppData/Roaming/<app_name>`
- Other platforms: `.` (current directory)

`~` is resolved via the `home` crate. If `home_dir()` returns `None`, `"~"` is used literally as the base (which usually results in a relative directory named `~`).

#### `config_path`

```rust
pub fn config_path(app_name: &str, file_name: &str) -> PathBuf
```

`config_dir(app_name).join(file_name)`.

### File-level helpers

These mirror `fs::v1::config` but return `Result`:

#### `get`

```rust
pub fn get(app_name: &str, file_path: &str, def_content: Option<&str>) -> Result<String, ConfigError>
```

Reads the config file, creating it from `def_content` if missing. Returns `ConfigError::Io` when the file does not exist and no default is provided, or when read/write fails.

#### `rewrite`

```rust
pub fn rewrite(app_name: &str, file_path: &str, json_content: &str) -> Result<(), ConfigError>
```

Writes `json_content` with `write_atomic`. Creates parents. Does **not** validate that `json_content` is valid JSON.

#### `get_value`

```rust
pub fn get_value(json_element: &Value, key: &str) -> Option<Value>
```

Top-level lookup only (no dot-separated paths). Returns `None` if `json_element` is not an object or the key is missing.

#### `parse_value_as`

```rust
pub fn parse_value_as<T: DeserializeOwned>(val: &Value) -> Option<T>
```

Deserializes a `Value` into `T`, returning `None` on mismatch.

### `ConfigError`

```rust
pub enum ConfigError {
    Io(std::io::Error),
    Parse(serde_json::Error),
    KeyNotFound(String),
    TypeMismatch { key: String, expected: &'static str },
    InvalidKeyPath(String),
}
```

Implements `Display`, `Error` (with `source()` returning the inner `io::Error` / `serde_json::Error` for the first two variants), `From<std::io::Error>` and `From<serde_json::Error>`.

```rust
match cfg.get_as::<i32>("x") {
    Ok(v) => println!("{v}"),
    Err(ConfigError::KeyNotFound(k)) => eprintln!("missing key: {k}"),
    Err(ConfigError::TypeMismatch { key, expected }) => {
        eprintln!("key `{key}` is not a {expected}");
    }
    Err(e) => eprintln!("error: {e}"),
}
```

## Behavior notes and differences from v1

- `fs-v2` has **no compile-time dependency** on `types` or `color`.
- The config API returns `Result<_, ConfigError>` instead of panicking.
- `new_dir` returns `bool` instead of panicking.
- `write` accepts `AsRef<Path>` and returns `io::Result` for parent creation; v1 panics via `new_dir`.
- `write_atomic` is new in v2.
- `normalize` respects the filesystem root; `fs::v1::normalize_path` does not.
- The typed `Config` type is new in v2; v1 only exposes raw-string helpers.
