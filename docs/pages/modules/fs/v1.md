# fs::v1

Filesystem primitives and JSON configuration helpers, first generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["fs-v1", "types-v1", "color-v1"] }
```

`fs-v1` requires `types-v1` or `types-v2`, which in turn require `color-v1` or `color-v2`. The reason is that some fs helpers print colored `Status` messages.

When `fs-v1` is enabled, its public items are re-exported at `musutils::fs::*`; the configuration API lives under `musutils::fs::config::*`.

```rust
use musutils::fs::{copy, copy_dir_all, new_dir, write, tilda_desir};
use musutils::fs::config::{get, get_value, parse_value_as, rewrite};
```

## Purpose

`fs::v1` is a set of thin helpers on top of `std::fs` that the author wanted to have in one place: copying, writing, creating and removing directories, checking existence, path normalization, tilde expansion, plus a small JSON-configuration store under the user's config directory.

Most functions delegate directly to `std`. The helpers that add behavior on top of `std` are `tilda_desir`, `new_dir` and `write`, and the `config` submodule.

## Filesystem primitives

### `copy`

```rust
pub fn copy<P: AsRef<Path>, Q: AsRef<Path>>(from: P, to: Q) -> io::Result<u64>
```

Copies a file, returning the number of bytes copied. Thin wrapper over `std::fs::copy` — overwrites `to` if it exists and the OS allows it, and inherits the file's permissions.

```rust
use musutils::fs::copy;

let n = copy("a.txt", "b.txt")?;
assert_eq!(n, 5);
```

Errors are the same as for `std::fs::copy`: missing source, permission denied, etc. The destination directory is **not** created.

### `copy_dir_all`

```rust
pub fn copy_dir_all<P: AsRef<Path>, Q: AsRef<Path>>(from: P, to: Q) -> io::Result<()>
```

Recursively copies `from` into `to`, creating `to` (and its parents) if needed.

- Directories are recreated with `std::fs::create_dir_all`.
- Files are copied with `std::fs::copy`.
- Symlinks are followed: `entry.file_type()?.is_dir()` decides whether to recurse or copy, and `file_type()` of a symlink reports the target's type.

```rust
use musutils::fs::copy_dir_all;

copy_dir_all("src_tree", "dst_tree")?;
```

Errors are surfaced as `io::Result` — a missing source, permission errors, or an unreadable directory inside the tree.

### `get_curr_dir`

```rust
pub fn get_curr_dir() -> PathBuf
```

Returns `std::env::current_dir()`. **Panics** if the current directory cannot be obtained (for example, when it has been removed).

```rust
use musutils::fs::get_curr_dir;

let cwd = get_curr_dir();
```

Use `std::env::current_dir()` directly if you want a `Result` instead of a panic.

### `is_exist`

```rust
pub fn is_exist<P: AsRef<Path>>(path: P) -> bool
```

Returns `true` if the path exists after tilde expansion and normalization via [`tilda_desir`](#tilda_desir).

```rust
use musutils::fs::is_exist;

assert!(is_exist("/tmp"));
assert!(!is_exist("/tmp/definitely-does-not-exist-xyz"));
```

Note: this follows the same rules as `Path::exists()` — a path whose parent lacks search permission returns `false`, not an error.

### `new_dir`

```rust
pub fn new_dir<P: AsRef<Path>>(path: P) -> bool
```

Creates a directory (and any missing parents) after tilde expansion and normalization. Returns `true` on success.

**Panics** on any failure with the message `"{colored Status::Err}: can't create dir"`. The panic uses `Status::Err.as_colored_str()` from the [`types`](../types/v1.md) module, which is why `fs-v1` requires `types`.

```rust
use musutils::fs::new_dir;

assert!(new_dir("/tmp/musutils-demo/nested/dir"));
```

Creating an existing directory is not an error (`create_dir_all` semantics). Trying to create a directory inside a regular file panics.

### `normalize_path`

```rust
pub fn normalize_path(path: &Path) -> PathBuf
```

Lexically normalizes a path:

- `Component::CurDir` (`.`) is dropped.
- `Component::ParentDir` (`..`) pops the previous component, **even if that component is a root or prefix**.
- All other components are pushed as-is.

It does **not** touch the filesystem, does not resolve symlinks, and does not check whether the resulting path exists.

```rust
use std::path::{Path, PathBuf};
use musutils::fs::normalize_path;

assert_eq!(normalize_path(Path::new("a/./b/../c")), PathBuf::from("a/c"));
assert_eq!(normalize_path(Path::new("")), PathBuf::new());
assert_eq!(normalize_path(Path::new(".")), PathBuf::new());
```

Careful: in v1, `normalize_path(Path::new("/.."))` returns an empty `PathBuf`, not `/`. This is one of the behavioral differences from [`fs::v2::normalize`](v2.md#normalize), which keeps `/`.

### `remove_dir_all`

```rust
pub fn remove_dir_all<P: AsRef<Path>>(path: P) -> io::Result<()>
```

Thin wrapper over `std::fs::remove_dir_all`. Removes the directory and all its contents. Returns an error if `path` does not exist or is not a directory.

```rust
use musutils::fs::remove_dir_all;

remove_dir_all("/tmp/musutils-demo")?;
```

### `tilda_desir`

```rust
pub fn tilda_desir<P: AsRef<Path>>(path: P) -> PathBuf
```

Expands a leading `~` to the user's home directory, joins relative paths with the current directory, and normalizes the result with [`normalize_path`](#normalize_path).

Behavior:

- `~` → the home directory (via the `home` crate).
- `~/…` → `home/…`.
- A relative path (not starting with `~`) → `cwd.join(path)`.
- An absolute path → returned as-is.
- In every case the result is passed through `normalize_path`.

```rust
use std::path::PathBuf;
use musutils::fs::tilda_desir;

let home = tilda_desir("~");
let sub  = tilda_desir("~/sub/file.txt");   // home/sub/file.txt
let rel  = tilda_desir("rel/x");            // cwd/rel/x
let abs  = tilda_desir("/tmp/abs");         // /tmp/abs
```

If the home directory cannot be determined, the path is returned unchanged (after normalization). On Windows, `home::home_dir()` reads `USERPROFILE`.

### `write`

```rust
pub fn write<C: AsRef<[u8]>>(path: PathBuf, content: C) -> io::Result<()>
```

Writes `content` to `path`, creating missing parent directories first.

- `path` must be a `PathBuf` — unlike the other helpers in this module, `write` does not take `AsRef<Path>`, and it does **not** do tilde expansion.
- If `path.parent()` is non-empty and does not exist, `new_dir(parent)` is called. Since `new_dir` panics on failure, a permission error on the parent directory surfaces as a **panic** from `new_dir`, not as an `io::Error` from `write`.
- The file is opened with `File::create`, so it is truncated if it already exists.

```rust
use musutils::fs::write;

write("a/b/c.txt".into(), b"payload")?;
```

### `write_bytes`

```rust
pub fn write_bytes<P: AsRef<Path>, C: AsRef<[u8]>>(path: P, contents: C) -> io::Result<()>
```

Thin wrapper over `std::fs::write`. Does **not** create missing parents and does **not** do tilde expansion.

```rust
use musutils::fs::write_bytes;

write_bytes("/tmp/x.bin", [0u8, 1, 2, 255])?;
```

### `test`

```rust
pub fn test()
```

Prints `"Meow"` to stdout. It is a smoke-test helper with no practical use in a library; it exists in both `fs::v1` and `fs::v2` (v2 prints an ASCII cat).

## Configuration (`fs::config`)

The `fs::config` submodule stores JSON files under the platform config directory:

- Linux and macOS: `~/.config/<app_name>/<file_path>`
- Windows: `~/AppData/Roaming/<app_name>/<file_path>`

The base directory is computed with `tilda_desir`, so `~` expansion and normalization apply.

The submodule operates on the raw file contents as `String` / `serde_json::Value`. It does **not** maintain a `Config` object — loading, mutating and saving are separate calls (see [`fs::v2::config`](v2.md#configuration-fsv2config) for the typed API).

### `config::get`

```rust
pub fn get(app_name: &str, file_path: &str, def_content: Option<&str>) -> String
```

Reads a configuration file, creating it from `def_content` if it does not exist.

- If the file does not exist **and** `def_content` is `Some`, the default is written (creating parent directories via `new_dir`) and returned.
- Otherwise the file is read and its contents returned.

**Panics** if the file does not exist and `def_content` is `None`, if the parent directories cannot be created, or if the file exists but cannot be read.

```rust
use musutils::fs::config::get;

let content = get("myapp", "conf.json", Some(r#"{"theme":"dark"}"#));
```

### `config::rewrite`

```rust
pub fn rewrite(app_name: &str, file_path: &str, json_content: &str)
```

Writes `json_content` to the config file, creating parent directories. **Panics** on any write error.

```rust
use musutils::fs::config::{get, rewrite};

rewrite("myapp", "conf.json", r#"{"theme":"light"}"#);
assert_eq!(get("myapp", "conf.json", None), r#"{"theme":"light"}"#);
```

### `config::get_value`

```rust
pub fn get_value(json_element: &Value, key: &str) -> Option<Value>
```

Looks up `key` at the **top level** of a JSON object and clones the value. Returns `None` if `json_element` is not an object or the key is missing. Nested lookup is not supported — use `serde_json` directly for that, or [`fs::v2::Config::get`](v2.md#get).

```rust
use serde_json::json;
use musutils::fs::config::get_value;

let v = json!({"a": 1, "b": "x"});
assert_eq!(get_value(&v, "a"), Some(json!(1)));
assert_eq!(get_value(&v, "nope"), None);
```

### `config::parse_value_as`

```rust
pub fn parse_value_as<T: DeserializeOwned>(val: &Value) -> Option<T>
```

Deserializes a `serde_json::Value` into `T`, returning `None` on type mismatch.

```rust
use serde_json::json;
use musutils::fs::config::parse_value_as;

assert_eq!(parse_value_as::<i32>(&json!(7)), Some(7));
assert_eq!(parse_value_as::<i32>(&json!("str")), None);
```

## Behavior notes and differences from v2

- `get_curr_dir`, `new_dir` and the `config` helpers **panic** on failure. `fs::v2` returns `Result` for the same operations.
- `normalize_path` removes `..` unconditionally; `fs::v2::normalize` keeps `..` when it cannot be resolved against a normal component.
- `tilda_desir` here matches `fs::v2::expand` (also aliased as `tilda_desir` in v2).
- `write` takes `PathBuf` and panics via `new_dir` if parents cannot be created; `fs::v2::write` takes `AsRef<Path>` and returns `io::Result`.
- There is no atomic write in v1. `fs::v2::write_atomic` writes to a temporary file first.
- The config API works with raw strings/`Value`; v2 provides a typed `Config` with `get` / `set` / `save` and a `ConfigError` error type.
