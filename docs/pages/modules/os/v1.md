# os::v1

Operating system and architecture detection, first generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["os-v1"] }
```

`os-v1` has no inter-module dependencies.

When `os-v1` is enabled, its public items are re-exported at `musutils::os::*`:

```rust
use musutils::os::{OS, Arch, get_os, get_arch};
```

## Purpose

`os::v1` reports the operating system and CPU architecture the crate was **compiled for**. Detection is purely compile-time — it uses `cfg!(target_os = …)` and `cfg!(target_arch = …)`, so it never touches the filesystem or environment. It is useful for choosing release binaries, printing diagnostics, or gating behavior that cannot be expressed as a feature.

## `OS`

```rust
pub enum OS {
    Windows,
    Linux,
    MacOs,
    Unknown,
}
```

`OS` in v1 derives **nothing** — no `Debug`, no `Clone`/`Copy`, no `PartialEq`/`Eq`, no `Hash`. To compare values you must use pattern matching:

```rust
use musutils::os::{get_os, OS};

match get_os() {
    OS::Linux => println!("linux"),
    OS::Windows => println!("windows"),
    OS::MacOs => println!("macos"),
    OS::Unknown => println!("unknown"),
}
```

`OS` does not implement `Display` in v1 — there is no string form.

## `Arch`

```rust
pub enum Arch {
    X86,
    X64,
    Arm,
    Arm64,
    Unknown,
}
```

Like `OS`, v1's `Arch` does not derive any traits and has no string representation.

## `get_os`

```rust
pub fn get_os() -> OS
```

Returns the OS the crate was built for:

| `target_os` | Return value     |
|-------------|------------------|
| `windows`   | `OS::Windows`    |
| `linux`     | `OS::Linux`      |
| `macos`     | `OS::MacOs`      |
| anything else | `OS::Unknown`  |

The function is a chain of `cfg!` checks — no runtime detection, no environment lookups.

```rust
use musutils::os::{get_os, OS};

if matches!(get_os(), OS::Linux) {
    println!("running on linux");
}
```

## `get_arch`

```rust
pub fn get_arch() -> Arch
```

Returns the CPU architecture the crate was built for:

| `target_arch` | Return value     |
|---------------|------------------|
| `x86_64`      | `Arch::X64`      |
| `x86`         | `Arch::X86`      |
| `aarch64`     | `Arch::Arm64`    |
| `arm`         | `Arch::Arm`      |
| anything else | `Arch::Unknown`  |

```rust
use musutils::os::{get_arch, Arch};

if matches!(get_arch(), Arch::X64 | Arch::Arm64) {
    println!("64-bit");
}
```

## Limitations

- Results reflect the **compile target**, not the runtime host. A binary compiled for `x86_64-linux` reports `Linux` + `X64` even when run under an emulator, WSL, or a container.
- Only four operating systems and four architectures are recognized. Anything else returns `Unknown` — this is not an error.
- Because the enums do not derive `Debug`, they cannot be printed with `{:?}`, and v1 provides no `as_str` alternative. If you need strings or comparisons, use [`os::v2`](v2.md).

## Differences from v2

- **Derives** — v1 enums derive nothing; v2 derives `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`.
- **Strings** — v2 adds `as_str()` and `Display`. v1 has none.
- **API shape** — identical function names (`get_os`, `get_arch`) and variant names.

The detection logic itself is the same in both generations.
