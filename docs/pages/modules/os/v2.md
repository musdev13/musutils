# os::v2

Operating system and architecture detection, second generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["os-v2"] }
```

`os-v2` has no inter-module dependencies.

When `os-v2` is enabled, its public items are re-exported at `musutils::os::*`:

```rust
use musutils::os::{OS, Arch, get_os, get_arch};
```

## Purpose

`os::v2` reports the operating system and CPU architecture the crate was **compiled for**, using `cfg!(target_os = …)` and `cfg!(target_arch = …)`. It keeps the same detection logic and variant names as [`os::v1`](v1.md) but adds the traits and string representations that make the enums usable in ordinary code: `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`, `Display`, and `as_str()`.

## `OS`

```rust
pub enum OS {
    Windows,
    Linux,
    MacOs,
    Unknown,
}
```

Derives `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`.

### `OS::as_str`

```rust
pub fn as_str(&self) -> &'static str
```

| Variant     | `as_str()`   |
|-------------|--------------|
| `Windows`   | `"windows"`  |
| `Linux`     | `"linux"`    |
| `MacOs`     | `"macos"`    |
| `Unknown`   | `"unknown"`  |

The returned strings are lowercase and stable — they are suitable for machine-readable output. They are **not** guaranteed to match `std::env::consts::OS`; that constant uses `"macos"` too, but this crate does not promise alignment for future targets.

```rust
use musutils::os::OS;

assert_eq!(OS::Linux.as_str(), "linux");
assert_eq!(OS::MacOs.as_str(), "macos");
```

### `Display` for `OS`

`Display` writes `as_str()`.

```rust
use musutils::os::OS;

assert_eq!(OS::Windows.to_string(), "windows");
```

### `Eq` / `Hash`

`OS` can be compared with `==` and used as a `HashMap` key or `HashSet` element.

```rust
use std::collections::HashSet;
use musutils::os::OS;

let mut seen = HashSet::new();
seen.insert(OS::Linux);
seen.insert(OS::Linux);
assert_eq!(seen.len(), 1);
```

## `Arch`

```rust
pub enum Arch {
    X86,
    X64,
    Arm,
    Arm64,
    Unknown,
}
```

Derives `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`.

### `Arch::as_str`

```rust
pub fn as_str(&self) -> &'static str
```

| Variant   | `as_str()`    |
|-----------|---------------|
| `X86`     | `"x86"`       |
| `X64`     | `"x86_64"`    |
| `Arm`     | `"arm"`       |
| `Arm64`   | `"aarch64"`   |
| `Unknown` | `"unknown"`   |

The strings match the Rust target triple names for the architecture component (`x86_64`, `aarch64`, …), except `X86` which returns `"x86"` (Rust's target name is `i686`).

### `Display` for `Arch`

`Display` writes `as_str()`.

```rust
use musutils::os::Arch;

assert_eq!(Arch::X64.to_string(), "x86_64");
```

## `get_os`

```rust
pub fn get_os() -> OS
```

Returns the OS the crate was built for:

| `target_os` | Return value     |
|-------------|------------------|
| `windows`   | `OS::Windows`    |
| `linux`     | `OS::Linux`      |
| `macos`     | `OS::MacOs`      |
| anything else | `OS::Unknown`  |

```rust
use musutils::os::{get_os, OS};

if get_os() == OS::Linux {
    println!("linux build");
}
```

## `get_arch`

```rust
pub fn get_arch() -> Arch
```

Returns the CPU architecture the crate was built for:

| `target_arch` | Return value     |
|---------------|------------------|
| `x86_64`      | `Arch::X64`      |
| `x86`         | `Arch::X86`      |
| `aarch64`     | `Arch::Arm64`    |
| `arm`         | `Arch::Arm`      |
| anything else | `Arch::Unknown`  |

```rust
use musutils::os::{get_arch, Arch};

let bits = match get_arch() {
    Arch::X64 | Arch::Arm64 => 64,
    Arch::X86 | Arch::Arm     => 32,
    Arch::Unknown            => 0,
};
```

## Diagnostics helper

Both enums are `Debug`, so a one-line diagnostic is straightforward:

```rust
use musutils::os::{get_arch, get_os};

eprintln!("target: {} / {}", get_os(), get_arch());
```

## Limitations

- Results reflect the **compile target**, not the runtime host. Cross-compiled binaries report the target they were built for.
- Only four operating systems and four architectures are recognized; anything else returns `Unknown`.
- Detection is compile-time only — there is no way to override it at runtime.

## Differences from v1

- **Derives** — v2 adds `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash` to both enums.
- **Strings** — v2 adds `as_str()` and `Display`.
- **Function names and variants** — unchanged from v1.

The detection logic itself is identical between generations.
