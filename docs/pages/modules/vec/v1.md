# vec::v1

Pagination and JSON table printing, first generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["vec-v1"] }
```

`vec-v1` has no inter-module dependencies.

When `vec-v1` is enabled, its public items are re-exported at `musutils::vec::*`:

```rust
use musutils::vec::{get_page, print_json_as_table};
```

## Purpose

`vec::v1` contains two helpers used by CLI tools:

- `get_page` — slices a page out of a slice, with **0-based** page numbering.
- `print_json_as_table` — prints a vector of JSON objects as an aligned text table.

Both are simple and infallible; the table printer writes to stdout directly. See [`vec::v2`](v2.md) for a 1-based `page` returning `Result`, and a `json_as_table` that returns a `String` (with adjustable column widths).

## `get_page`

```rust
pub fn get_page<T: Clone>(items: &[T], page: u32, count: u32) -> Vec<T>
```

Returns the `count` items starting at index `page * count`.

- `page` is **0-based**: `page = 0` returns the first page.
- `count` is the page size (items per page).
- Elements are `clone()`d — the returned vector is independent of the input.

```rust
use musutils::vec::get_page;

let v = vec![1, 2, 3, 4, 5];
assert_eq!(get_page(&v, 0, 2), vec![1, 2]);
assert_eq!(get_page(&v, 1, 2), vec![3, 4]);
assert_eq!(get_page(&v, 2, 2), vec![5]);
```

Edge cases:

- `count == 0` → empty `Vec` for any page.
- Page past the end → empty `Vec`.
- `count` larger than the remaining items → returns whatever is left (does not pad).
- Empty input → empty `Vec`.
- `page * count` may overflow `u32` before being cast to `usize`; this is not guarded in v1.

```rust
use musutils::vec::get_page;

let v = vec![1, 2, 3];
assert!(get_page(&v, 100, 10).is_empty());
assert!(get_page(&v, 0, 0).is_empty());
assert_eq!(get_page(&v, 0, 100), vec![1, 2, 3]);
```

## `print_json_as_table`

```rust
pub fn print_json_as_table(json_vec: &[Value])
```

Prints a table of JSON objects to **stdout**.

- The **first** element of the slice determines the set of columns. Its object keys are used, in `serde_json`'s map iteration order.
- Each column is padded to 25 characters with `format!("{:<25}", …)`.
- Rows are joined with `" | "`, and a `"-"`-separator line is printed above and below the table.
- String values are printed without quotes; other JSON values are printed via `Display` (so numbers, `true`/`false`, `null` are rendered naturally).
- A key missing from a row is printed as `"N/A"`.
- Elements of `json_vec` that are not objects are **skipped** — no row is printed for them.

When the input is empty, prints:

```text
No data to display.
```

When the first element is not an object (or has no keys), prints:

```text
No fields to display.
```

```rust
use musutils::vec::print_json_as_table;
use serde_json::json;

print_json_as_table(&[
    json!({"name": "alpha", "size": 1}),
    json!({"name": "beta",  "size": 22}),
]);
```

Output (approximately):

```text
name                     | size
--------------------------------------
alpha                    | 1
beta                     | 22
--------------------------------------
```

Behavior notes:

- Because only the **first** element decides the columns, keys that appear only in later rows are not shown.
- Column width is fixed at 25 characters regardless of content; values longer than 25 characters make the rows longer than the separator. There is no wrapping.
- Printing is done with `println!`, so output ends with a newline. There is no `String`-returning variant in v1; if you need the table as a `String`, use [`vec::v2::json_as_table`](v2.md#json_as_table).
- The `N/A` marker appears when a **later** object is missing a key from the first row.

## Limitations

- `get_page` is 0-based, which is easy to misread. `vec::v2::page` uses 1-based numbering to match user-facing concepts like "page 1 of N".
- `get_page` does not check `page * count` for `u32` overflow — passing very large values can produce a surprising index due to wrapping.
- `print_json_as_table` is terminal-only: you cannot capture its output as a string, and the table layout is fixed. `vec::v2::json_as_table` addresses both.

## Differences from v2

| Aspect | v1 | v2 |
|---|---|---|
| Pagination function | `get_page(&[T], page: u32, count: u32)` — 0-based | `get_page(&[T], page: u32, count: u32)` **and** `page(&[T], page: u32, per_page: u32) -> Result<Vec<T>, PageError>` — 1-based |
| Zero page size | Empty `Vec` | `get_page` empty; `page` returns `PageError::ZeroPerPage` |
| Table rendering | `print_json_as_table` — prints to stdout, fixed width | `json_as_table -> Result<String, TableError>` **and** `print_json_as_table` wrapping it |
| Column set | From the **first** object only | Union of keys across **all** objects |
| Column width | Fixed 25 | Computed per column from content |
| Error type | None | `PageError`, `TableError` |
