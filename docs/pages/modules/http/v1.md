# http::v1

HTTP helpers, first generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = [
    "http-v1",
    "fs-v1",
    "types-v1",
    "color-v1",
] }
```

`http-v1` requires `fs-v1` or `fs-v2`, and `types-v1` or `types-v2` (which themselves require `color-v1` or `color-v2`). The reason is that `download_to` writes files through `fs`, and `download_to_sha1` prints `Status` labels through `types`.

When `http-v1` is enabled, its public items are re-exported at `musutils::http::*`:

```rust
use musutils::http::{get_file, get_json_str, download_to, download_to_sha1, AsyncDownloader};
```

## Purpose

`http::v1` is a set of small helpers around `reqwest::get` for fetching bytes and JSON, downloading files to disk, and verifying their SHA-1 hash. It also includes an `AsyncDownloader` that runs a batch of downloads with bounded concurrency but **unbounded retries**.

There is no shared client — each call to `reqwest::get` creates a new `reqwest::Client` internally. See [`http::v2`](v2.md) for the version that reuses a client, respects HTTP status codes, and bounds retries.

## `get_file`

```rust
pub async fn get_file(url: String) -> std::io::Result<Vec<u8>>
```

Fetches `url` and returns the raw body bytes. Takes `String` (not `Into<String>`).

Behavior:

- Uses `reqwest::get(url)` — a new client per call.
- Does **not** check the HTTP status. A `404` response is returned as `Ok(body)`.
- Returns `io::Error` (via `io::Error::other`) for network errors or body read failures.

```rust
let bytes = musutils::http::get_file("https://example.com/data.bin".into()).await?;
```

## `get_json_str`

```rust
pub async fn get_json_str(url: String) -> std::io::Result<String>
```

Fetches `url`, parses the body as `serde_json::Value`, and returns the value pretty-printed with two-space indentation.

- Status code is not checked.
- Network / body errors → `io::Error`.
- Invalid JSON → `io::Error` (wrapped `serde_json::Error`).

```rust
let s = musutils::http::get_json_str("https://api.example.com/x".into()).await?;
println!("{s}");
```

## `get_github_json_str`

```rust
pub async fn get_github_json_str(url: String) -> std::io::Result<String>
```

Same as `get_json_str`, but sends the headers expected by the GitHub API:

- `Accept: application/vnd.github+json`
- `User-Agent: rml`

The `User-Agent` header is hard-coded to `"rml"` — a historical value inherited from another project. It is **not** something you should rely on; use `get_json_str` if you need a configurable user agent.

Status code is not checked; errors are as for `get_json_str`.

```rust
let release = musutils::http::get_github_json_str(
    "https://api.github.com/repos/musdev13/musutils/releases/latest".into(),
).await?;
```

## `download_to`

```rust
pub async fn download_to(url: String, path: PathBuf) -> std::io::Result<()>
```

Fetches `url` via `get_file` and writes the body to `path` using `fs::write`. Because `fs::write` calls `new_dir` to create missing parents, a permission error on the parent directory will **panic**, not return `io::Error`.

Takes `PathBuf` (not `AsRef<Path>`); does not create parents in v1's `fs::write` semantics for the file itself beyond what `fs::write` does.

Status code is not checked — a `404` body is written to disk.

```rust
use std::path::PathBuf;
use musutils::http::download_to;

download_to("https://example.com/x.bin".into(), PathBuf::from("/tmp/x.bin")).await?;
```

## `download_to_sha1`

```rust
pub async fn download_to_sha1(
    url: String,
    path: PathBuf,
    expected_sha1: String,
) -> std::io::Result<()>
```

Downloads `url` to `path` and verifies its SHA-1 against `expected_sha1`.

Algorithm — **infinite retry loop**:

1. Call `download_to(url, path)`.
2. On success, read the file, compute the SHA-1 (lowercase hex), and compare it to `expected_sha1` (**case-sensitive** — no normalization on either side).
3. On match — return `Ok(())`.
4. On mismatch — print a warning via `Status::Warn.as_colored_str()`, remove the file, loop immediately (no delay).
5. On download error — sleep for **1 second**, retry.

There is no retry limit and no way to break out of the loop from the outside. **The function returns `Ok(())` only on a verified download and never returns `Err`** in practice, because every error is swallowed by the retry loop. If the URL is permanently unreachable or the hash is wrong, the call never terminates.

Use [`http::v2::download_to_sha1`](v2.md#download_to_sha1) when you need a bounded number of retries and an `HttpError`.

```rust
use std::path::PathBuf;
use musutils::http::download_to_sha1;

download_to_sha1(
    "https://example.com/x.bin".into(),
    PathBuf::from("/tmp/x.bin"),
    "aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d".into(),
).await?;
```

## `AsyncDownloader`

```rust
pub struct AsyncDownloader { /* private */ }

pub enum HashAlgo {
    None,
    Sha1,
}

impl AsyncDownloader {
    pub fn new(max_concurrent: usize, algo: HashAlgo) -> Self;
    pub fn push(
        &mut self,
        url: String,
        path: PathBuf,
        hash: Option<String>,
        task_start_msg: Option<String>,
        success_msg: Option<String>,
    );
    pub async fn join(&mut self) -> std::io::Result<()>;
}
```

A batch downloader that runs tasks on a `tokio::task::JoinSet`, gated by a `tokio::sync::Semaphore` with `max_concurrent` permits.

### `HashAlgo`

- `HashAlgo::None` — downloads without verification.
- `HashAlgo::Sha1` — requires a hash in `push(…, Some(hash), …)`; if `hash` is `None`, falls through to the no-hash path.

### `AsyncDownloader::new`

```rust
pub fn new(max_concurrent: usize, algo: HashAlgo) -> Self
```

Creates a downloader. `max_concurrent == 0` is accepted but the semaphore immediately blocks all tasks (v1 does **not** clamp it to `1` — see v2). Only relevant if `join` is ever called.

### `AsyncDownloader::push`

```rust
pub fn push(
    &mut self,
    url: String,
    path: PathBuf,
    hash: Option<String>,
    task_start_msg: Option<String>,
    success_msg: Option<String>,
)
```

Schedules one download task. Message templates support two placeholders:

- `{0}` — file name extracted from `path` (`path.file_name()`); empty if `path` has no file name.
- `{1}` — `path.to_string_lossy()`.

`task_start_msg` is printed **after** acquiring the semaphore permit, before starting the download. `success_msg` is printed after a successful download.

Behavior of the spawned task:

- `HashAlgo::Sha1` + `Some(hash)` → calls `download_to_sha1` (with the infinite retry loop described above).
- Otherwise → calls `download_to` in a loop with a **1-second delay between failures**. This inner loop also has no retry limit.

In other words, a task returned by `push` will not return an error unless the semaphore is closed. HTTP failures and wrong hashes become permanent retries, not task errors.

### `AsyncDownloader::join`

```rust
pub async fn join(&mut self) -> std::io::Result<()>
```

Awaits all spawned tasks. Returns:

- `Ok(())` if all tasks completed successfully.
- `Err(io::Error)` for the **first** failed task — either a `JoinError` from `tokio` or an `io::Error` from a task. Remaining tasks are **not** awaited; they are dropped when `AsyncDownloader` is dropped.

Given the retry loops above, `join` is unlikely to return an error unless a task panics or the runtime is shutting down.

### Example

```rust
use std::path::PathBuf;
use musutils::http::{AsyncDownloader, async_downloader::HashAlgo};

let mut dl = AsyncDownloader::new(4, HashAlgo::None);
dl.push(
    "https://example.com/a.bin".into(),
    PathBuf::from("/tmp/a.bin"),
    None,
    Some("downloading {0}...".into()),
    Some("saved {0} -> {1}".into()),
);
dl.join().await?;
```

## Differences from v2

| Aspect | v1 | v2 |
|---|---|---|
| Client | New `reqwest::Client` per call | Shared `OnceLock<reqwest::Client>` with timeouts and pooling |
| HTTP status | Ignored | `HttpError::Status(code)` for non-2xx |
| Error type | `io::Error` | `HttpError` (typed) |
| Retries | Unbounded | `retries` parameter, exponential backoff |
| `download_to_sha1` | Infinite loop, never returns `Err` | Bounded, returns `HashMismatch` / `RetriesExceeded` |
| `AsyncDownloader` | No progress API | `progress()` and per-task errors |
| `get_github_json_str` User-Agent | `"rml"` | `"musutils"` |
