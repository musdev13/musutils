# http::v2

HTTP helpers with typed errors, a shared client, and bounded retries, second generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["http-v2"] }
```

`http-v2` is **self-contained** — it does not require `fs` or `types`. This is a deliberate change from `http-v1`, which pulled in both modules.

When `http-v2` is enabled, its public items are re-exported at `musutils::http::*`; `AsyncDownloader` and `HashAlgo` live under `musutils::http::async_downloader`:

```rust
use musutils::http::{get_file, get_json_str, get_github_json_str, download_to, download_to_sha1, HttpError};
use musutils::http::async_downloader::{AsyncDownloader, HashAlgo};
```

## Purpose

`http::v2` reworks [`http::v1`](v1.md) around a typed error type (`HttpError`), a shared `reqwest::Client` with sensible timeouts, HTTP status checking, and a bounded retry strategy with exponential backoff. It also turns `AsyncDownloader` into a structure with a progress API and per-task error reporting.

## Shared client

All functions in this module go through a single `reqwest::Client` created lazily in a `OnceLock`:

- connect timeout: 10 s
- request timeout: 30 s
- idle pool per host: 64 connections
- idle timeout: 90 s

The client is process-global and not configurable. If it cannot be constructed (which would indicate a TLS backend failure), the code falls back to `reqwest::Client::new()` (defaults).

## `get_file`

```rust
pub async fn get_file(url: impl Into<String>) -> Result<Vec<u8>, HttpError>
```

Fetches `url` through the shared client and returns the body bytes.

- Any **non-success status** (outside `200..=299`) → `HttpError::Status(code)`.
- Network errors → `HttpError::Request(reqwest::Error)`.
- Body read failure → `HttpError::Request`.

```rust
let bytes = musutils::http::get_file("https://example.com/data.bin").await?;
```

## `get_json_str`

```rust
pub async fn get_json_str(url: impl Into<String>) -> Result<String, HttpError>
```

Fetches `url` via `get_file`, decodes as UTF-8, parses JSON, and returns the value **pretty-printed**.

- Non-2xx status → `HttpError::Status(code)`.
- Non-UTF-8 body → `HttpError::Io(InvalidData)`.
- Invalid JSON → `HttpError::Io(InvalidData)`.
- Pretty-print failure (would not normally happen) → `HttpError::Io(InvalidData)`.

```rust
let s = musutils::http::get_json_str("https://api.example.com/x").await?;
```

## `get_github_json_str`

```rust
pub async fn get_github_json_str(url: impl Into<String>) -> Result<String, HttpError>
```

Like `get_json_str`, but adds GitHub-specific headers:

- `Accept: application/vnd.github+json`
- `User-Agent: musutils`

The `User-Agent` is `"musutils"` in v2 — a deliberate change from `"rml"` in v1.

- Non-2xx status → `HttpError::Status(code)`.
- JSON parse failure → `HttpError::Request` (the underlying `reqwest::Error` from `response.json()`).

Note: v2's failure variant for bad JSON from GitHub is `Request`, while `get_json_str` reports it as `Io`. Both are `HttpError`, but the variant differs.

```rust
let release = musutils::http::get_github_json_str(
    "https://api.github.com/repos/musdev13/musutils/releases/latest",
).await?;
```

## `download_to`

```rust
pub async fn download_to(url: impl Into<String>, path: impl AsRef<Path>) -> Result<(), HttpError>
```

Fetches `url` via `get_file` and writes the body to `path` using `tokio::fs::write`. Parent directories are created first with `tokio::fs::create_dir_all` if `path.parent()` is non-empty.

- Non-2xx status → `HttpError::Status(code)` — the file is **not** written.
- I/O errors (permissions, missing directories that cannot be created, write failure) → `HttpError::Io`.
- Network errors → `HttpError::Request`.

```rust
use std::path::PathBuf;
use musutils::http::download_to;

download_to("https://example.com/x.bin", PathBuf::from("/tmp/x.bin")).await?;
```

## `download_to_sha1`

```rust
pub async fn download_to_sha1(
    url: impl Into<String>,
    path: impl AsRef<Path>,
    expected_sha1: impl Into<String>,
    retries: u32,
) -> Result<(), HttpError>
```

Downloads a file and verifies its SHA-1 against `expected_sha1`, with a bounded number of retries.

Algorithm:

1. Normalize `expected_sha1` to lowercase (`to_lowercase()`).
2. For `attempt` in `0..=retries`:
   - Call `download_to(url, path)`.
   - On **permanent** error (`e.is_permanent()`, typically 4xx except `408` / `429`) — return immediately with that error.
   - On any other error — record it as `last` and continue.
   - On success — read the file, compute SHA-1 as lowercase hex, compare with `expected`.
     - Match → return `Ok(())`.
     - Mismatch → build `HttpError::HashMismatch { expected, actual }`, store as `last`, remove the file, continue.
   - If `attempt < retries`, sleep with exponential backoff: `min(200ms * 2^min(attempt, 4), 5s)`.
3. After the loop returns: `last.unwrap_or(HttpError::RetriesExceeded(retries))`.

Notes:

- **Case-sensitivity** — both the expected hash and the computed hash are lowercased, so `"AABB…"` and `"aabb…"` are equivalent.
- The **file is removed** on hash mismatch, so a successful return leaves the file in place, a `HashMismatch` error leaves it absent (last iteration), and a `Status` / `Request` error leaves it whatever it was before the call.
- `retries = 0` means exactly one attempt. `retries = 1` means up to two attempts.
- When `download_to` fails permanently (e.g. 404), the error is returned on the **first** attempt even if `retries > 0` — 4xx errors are not retried.
- When all retries fail with `HashMismatch` (no I/O errors), the returned error is the **last** `HashMismatch`, not `RetriesExceeded`.

```rust
use std::path::PathBuf;
use musutils::http::download_to_sha1;

download_to_sha1(
    "https://example.com/x.bin",
    PathBuf::from("/tmp/x.bin"),
    "aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d",
    3,
).await?;
```

## `HttpError`

```rust
pub enum HttpError {
    Request(reqwest::Error),
    Status(u16),
    Io(std::io::Error),
    HashMismatch { expected: String, actual: String },
    RetriesExceeded(u32),
}
```

Implements `Display`, `Error` (with `source()` returning the inner error for `Request` and `Io`), `From<reqwest::Error>` and `From<std::io::Error>`.

### `HttpError::is_permanent`

```rust
pub fn is_permanent(&self) -> bool
```

Returns `true` if retrying the same request is unlikely to help. Currently:

- `Status(code)` where `400 <= code < 500`, **excluding** `408` and `429` → `true`.
- Everything else → `false`.

```rust
assert!(HttpError::Status(404).is_permanent());
assert!(!HttpError::Status(429).is_permanent());
assert!(!HttpError::Status(500).is_permanent());
```

## `AsyncDownloader`

```rust
pub struct AsyncDownloader { /* private */ }

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum HashAlgo {
    None,
    Sha1,
}

impl AsyncDownloader {
    pub fn new(max_concurrent: usize, algo: HashAlgo) -> Self;
    pub fn with_retries(self, retries: u32) -> Self;
    pub fn push(
        &mut self,
        url: String,
        path: PathBuf,
        hash: Option<String>,
        task_start_msg: Option<String>,
        success_msg: Option<String>,
    );
    pub async fn join(&mut self) -> Result<(), Vec<HttpError>>;
    pub fn progress(&self) -> (usize, usize, usize);
}
```

Runs a batch of downloads on a `tokio::task::JoinSet`, gated by a `tokio::sync::Semaphore`, with per-task error collection and a live progress counter.

### `HashAlgo`

- `HashAlgo::None` — download without verification (delegates to `download_to`).
- `HashAlgo::Sha1` — requires a hash in `push(…, Some(hash), …)`. If `None`, falls through to the `None` path.

### `AsyncDownloader::new`

```rust
pub fn new(max_concurrent: usize, algo: HashAlgo) -> Self
```

Creates a downloader with default `retries = 25`. `max_concurrent == 0` is clamped to `1` — unlike v1, where zero permanently blocked all tasks.

### `AsyncDownloader::with_retries`

```rust
pub fn with_retries(mut self, retries: u32) -> Self
```

Builder-style method that overrides the retry count used by tasks spawned after this call. Applies to both `download_to` retries and the `download_to_sha1` retry parameter.

### `AsyncDownloader::push`

```rust
pub fn push(
    &mut self,
    url: String,
    path: PathBuf,
    hash: Option<String>,
    task_start_msg: Option<String>,
    success_msg: Option<String>,
)
```

Schedules one task and increments the `total` counter.

Message templates support:

- `{0}` — file name (`path.file_name()`).
- `{1}` — `path.to_string_lossy()`.

`task_start_msg` is printed after the semaphore permit is acquired, before the download starts. `success_msg` is printed after a successful download. Messages go to stdout via `println!`.

Task behavior:

- `HashAlgo::Sha1` + `Some(hash)` → `download_to_sha1(url, path, hash, retries)`.
- Otherwise → up to `retries + 1` attempts of `download_to`, with exponential backoff between attempts. Permanent errors (`is_permanent()`) abort the loop early.

On task completion, the downloader updates:

- `errors` counter (incremented on error),
- `done` counter (always incremented),
- the task result is stored in the `JoinSet` and collected by `join`.

### `AsyncDownloader::join`

```rust
pub async fn join(&mut self) -> Result<(), Vec<HttpError>>
```

Awaits all tasks. While waiting, every second it prints a progress line to stderr:

```text
  starting N download(s)...
  [k/N] done, E error(s), 1.2s elapsed, 3.4 task(s)/s
  [done] k/N completed, E error(s) in 1.5s
```

Returns:

- `Ok(())` if every task completed successfully.
- `Err(Vec<HttpError>)` with one entry per failed task otherwise. The vector preserves completion order, not insertion order.

`JoinError`s (panics / cancellation) are wrapped as `HttpError::Io(std::io::Error::other(join_err))`.

Joining an already-drained downloader returns `Ok(())` immediately.

### `AsyncDownloader::progress`

```rust
pub fn progress(&self) -> (usize, usize, usize)
```

Returns `(done, total, errors)`:

- `done` — number of tasks that have finished (successfully or not).
- `total` — number of `push` calls.
- `errors` — number of tasks that returned an error.

Safe to call concurrently from any thread; the counters are `AtomicUsize`.

### Example

```rust
use std::path::PathBuf;
use musutils::http::async_downloader::{AsyncDownloader, HashAlgo};

let mut dl = AsyncDownloader::new(4, HashAlgo::Sha1).with_retries(3);
dl.push(
    "https://example.com/a.bin".into(),
    PathBuf::from("/tmp/a.bin"),
    Some("aaf4c61ddcc5e8a2dabede0f3b482cd9aea9434d".into()),
    Some("downloading {0}...".into()),
    Some("saved {0} -> {1}".into()),
);
match dl.join().await {
    Ok(()) => println!("all downloads completed"),
    Err(errors) => {
        for e in errors {
            eprintln!("download failed: {e}");
        }
    }
}
```

## Differences from v1

| Aspect | v1 | v2 |
|---|---|---|
| Client | New per call | Shared, with timeouts and pooling |
| Status code | Ignored | Non-2xx → `HttpError::Status` |
| Error type | `io::Error` | `HttpError` |
| `download_to_sha1` | Infinite loop, never returns `Err` | Bounded retries, returns `HashMismatch` / `Status` / `RetriesExceeded` |
| `download_to_sha1` hash case | Case-sensitive | Case-insensitive (both sides lowercased) |
| `AsyncDownloader` retries | Unbounded | Bounded (`retries`, default 25) |
| `AsyncDownloader` progress | None | `progress()` |
| `AsyncDownloader` errors | First error only, remaining tasks dropped | All errors collected |
| `max_concurrent == 0` | Blocks forever | Clamped to 1 |
| `get_github_json_str` User-Agent | `"rml"` | `"musutils"` |
| Inter-module dependencies | `fs` + `types` | None |
