# types::v2

Status labels, line drawing, and a deprecated `deoption`, second generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["types-v2", "color-v2"] }
```

`types-v2` requires `color-v1` or `color-v2`.

When `types-v2` is enabled, its public items are re-exported at `musutils::types::*`; the line helpers live both at the module root and under `musutils::types::line`:

```rust
use musutils::types::{Status, draw, draw_colored};
use musutils::types::line;
```

## Purpose

`types::v2` keeps the v1 building blocks (`Status`, `deoption`, line drawing) and improves their ergonomics: `Status` gains `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`, and `Display`; the line helpers are re-exported at the module root; `deoption` is marked deprecated in favor of `Option` combinators.

## `Status`

```rust
pub enum Status {
    Ok,
    Err,
    Inf,
    Warn,
    Task,
    Note,
    Quote,
    No,
    Yes,
    Question,
    Option,
    Select,
    Status,
}
```

Derives `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`.

### `Status::as_str`

```rust
pub fn as_str(&self) -> &'static str
```

Same labels as in v1:

| Variant    | `as_str()`    |
|------------|---------------|
| `Ok`       | `"!Ok"`       |
| `Err`      | `"!Err"`      |
| `Inf`      | `":Info"`     |
| `Warn`     | `"!Warn"`     |
| `Task`     | `":Task"`     |
| `Note`     | `":!Note"`    |
| `Quote`    | `":>Quote"`   |
| `No`       | `"!No"`       |
| `Yes`      | `"!Yes"`      |
| `Question` | `"?Question"` |
| `Option`   | `":?Option"`  |
| `Select`   | `":?Select"`  |
| `Status`   | `":Status"`   |

```rust
use musutils::types::Status;

assert_eq!(Status::Ok.as_str(), "!Ok");
```

### `Status::as_plain_str`

```rust
pub fn as_plain_str(&self) -> &'static str
```

Alias for [`as_str`](#statusas_str). Identical output.

### `Status::as_colored_str`

```rust
pub fn as_colored_str(&self) -> String
```

Same colors as in v1:

| Variant                         | Color    |
|---------------------------------|----------|
| `Ok`, `Yes`                     | `Lime`   |
| `Err`, `No`                     | `Rose`   |
| `Warn`                          | `Orange` |
| `Inf`, `Status`, `Task`         | `Gold`   |
| `Note`, `Select`, `Option`      | `Yellow` |
| `Quote`                         | `Gray`   |
| `Question`                      | `Purple` |

The result always ends with `"\x1b[0m"`. The function does **not** consult `NO_COLOR` / `CLICOLOR` / `TERM` / `IsTerminal` — like v1, it always colorizes.

```rust
use musutils::types::Status;

assert_eq!(Status::Ok.as_colored_str(), "\x1b[92m!Ok\x1b[0m");
```

### `Display` for `Status`

`Display` writes `as_str()` — the **plain** label, without escape sequences.

```rust
use musutils::types::Status;

assert_eq!(Status::Err.to_string(), "!Err");
```

This is useful for logging where you do not want ANSI escape codes to leak into log files:

```rust
eprintln!("{}: something happened", Status::Warn); // prints "!Warn: something happened"
```

### `Eq` / `Hash`

`Status` can be compared with `==` and used as a map key.

```rust
use std::collections::HashSet;
use musutils::types::Status;

let mut seen = HashSet::new();
seen.insert(Status::Ok);
seen.insert(Status::Ok);
assert_eq!(seen.len(), 1);
```

## `deoption`

```rust
#[deprecated(note = "use `Option::unwrap_or_else` or `Option::unwrap_or` instead")]
pub fn deoption<T, F>(opt: Option<T>, default_fn: F, found: &mut bool) -> T
where
    F: FnOnce() -> T,
```

Same behavior as [`types::v1::deoption`](v1.md#deoption) — returns the value or the default, and sets `*found` to indicate which branch was taken — but marked deprecated. Existing code still compiles; new code should prefer:

```rust
let found = opt.is_some();
let value = opt.unwrap_or_else(default_fn);
```

Because `deoption` is `#[deprecated]`, calling it triggers a compiler warning unless you add `#[allow(deprecated)]` in the calling scope.

## Line drawing

The line helpers are available both at the module root and under `musutils::types::line` in v2:

```rust
use musutils::types::{draw, draw_colored};
// or
use musutils::types::line::{draw, draw_colored};
```

Both paths refer to the same functions.

### `draw`

```rust
pub fn draw(c: char, count: usize) -> String
```

Repeats `c` `count` times. Same as `types::v1::line::draw`.

```rust
use musutils::types::draw;

assert_eq!(draw('-', 0), "");
assert_eq!(draw('x', 5), "xxxxx");
assert_eq!(draw('🦀', 2), "🦀🦀");
```

### `draw_colored`

```rust
pub fn draw_colored(c: char, count: usize, color: Colors) -> String
```

Wraps `draw(c, count)` once in the color escape sequence for `color`.

```rust
use musutils::color::Colors;
use musutils::types::draw_colored;

assert_eq!(draw_colored('*', 3, Colors::Red), "\x1b[31m***\x1b[0m");
```

## Practical example

Using `Status` with `Display` for plain logging, and `as_colored_str` for terminal output:

```rust
use musutils::types::Status;

fn report(s: Status, message: &str) {
    if std::io::IsTerminal::is_terminal(&std::io::stdout()) {
        println!("{} {}", s.as_colored_str(), message);
    } else {
        println!("{} {}", s, message);
    }
}

report(Status::Ok, "build finished");
report(Status::Warn, "cache is stale");
```

## Limitations

- `as_colored_str` is unconditional. For terminal-aware coloring use [`color::v2::color_str_auto`](../color/v2.md#color_str_auto) with your own label.
- `deoption` is deprecated but still present; removing it would be a breaking change.
- `draw` allocates a new `String` per call.

## Differences from v1

| Aspect | v1 | v2 |
|---|---|---|
| `Status` traits | none | `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`, `Display` |
| `Status::as_plain_str` | absent | present |
| `Display` on `Status` | absent | writes the plain label |
| Line helper paths | only `types::line::*` | root re-exports **and** `types::line::*` |
| `deoption` | available | available, `#[deprecated]` |
