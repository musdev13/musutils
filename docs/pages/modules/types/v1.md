# types::v1

Status labels, a small `deoption` helper, and line drawing, first generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["types-v1", "color-v1"] }
```

`types-v1` requires `color-v1` or `color-v2`. The reason is that `Status::as_colored_str` and `line::draw_colored` call into the color module.

When `types-v1` is enabled, its public items are re-exported at `musutils::types::*`; the line helpers live under `musutils::types::line`:

```rust
use musutils::types::{Status, deoption};
use musutils::types::line::{draw, draw_colored};
```

## Purpose

`types::v1` contains small types and helpers used elsewhere in the crate and in CLI applications:

- `Status` — a fixed set of labeled prefixes (`!Ok`, `!Err`, `:Info`, …) with an optional colored variant.
- `deoption` — a helper that picks between an `Option<T>` and a lazily-evaluated default, recording which branch was taken.
- `line::draw` / `line::draw_colored` — repeat a character N times, optionally colorized.

## `Status`

```rust
pub enum Status {
    Ok,
    Err,
    Inf,
    Warn,
    Task,
    Note,
    Quote,
    No,
    Yes,
    Question,
    Option,
    Select,
    Status,
}
```

In v1, `Status` does **not** derive any traits — no `Debug`, no `Clone`/`Copy`, no `PartialEq`/`Eq`, no `Hash`, no `Display`. Compare with pattern matching.

### `Status::as_str`

```rust
pub fn as_str(&self) -> &'static str
```

Returns the plain-text label:

| Variant    | `as_str()`    |
|------------|---------------|
| `Ok`       | `"!Ok"`       |
| `Err`      | `"!Err"`      |
| `Inf`      | `":Info"`     |
| `Warn`     | `"!Warn"`     |
| `Task`     | `":Task"`     |
| `Note`     | `":!Note"`    |
| `Quote`    | `":>Quote"`   |
| `No`       | `"!No"`       |
| `Yes`      | `"!Yes"`      |
| `Question` | `"?Question"` |
| `Option`   | `":?Option"`  |
| `Select`   | `":?Select"`  |
| `Status`   | `":Status"`   |

```rust
use musutils::types::Status;

assert_eq!(Status::Ok.as_str(), "!Ok");
assert_eq!(Status::Warn.as_str(), "!Warn");
```

### `Status::as_colored_str`

```rust
pub fn as_colored_str(&self) -> String
```

Returns the label wrapped in a color escape via `color::color_str`. The colors are:

| Variant             | Color         |
|---------------------|---------------|
| `Ok`, `Yes`         | `Lime`        |
| `Err`, `No`         | `Rose`        |
| `Warn`              | `Orange`      |
| `Inf`, `Status`, `Task` | `Gold`    |
| `Note`, `Select`, `Option` | `Yellow` |
| `Quote`             | `Gray`        |
| `Question`          | `Purple`      |

The result always ends with the reset sequence `"\x1b[0m"`. Unlike `color::v2::color_str_auto`, this **always** colorizes — it does not check `NO_COLOR` or whether stdout is a terminal.

```rust
use musutils::types::Status;

let s = Status::Err.as_colored_str();
assert!(s.contains("!Err"));
assert!(s.ends_with("\x1b[0m"));
```

## `deoption`

```rust
pub fn deoption<T, F>(opt: Option<T>, default_fn: F, found: &mut bool) -> T
where
    F: FnOnce() -> T,
```

Returns `opt.unwrap_or_else(default_fn)`, and sets `*found` to indicate which branch was taken.

- `Some(val)` → returns `val`, sets `*found = true`. `default_fn` is **not** called.
- `None` → calls `default_fn()`, returns its result, sets `*found = false`.

```rust
use musutils::types::deoption;

let mut found = false;
let v = deoption(Some(42), || 0, &mut found);
assert_eq!(v, 42);
assert!(found);

let mut found = true;
let v = deoption::<i32, _>(None, || 7, &mut found);
assert_eq!(v, 7);
assert!(!found);
```

`deoption` is deprecated in [`types::v2`](v2.md#deoption) — in ordinary code you can use `opt.is_some()` plus `unwrap_or_else` instead. It is kept in v1 for compatibility.

## Line drawing

The `line` submodule lives under `musutils::types::line`. In v1 it is a directory (`line/`) with two files; the API mirrors what v2 exposes at the `types` root.

### `line::draw`

```rust
pub fn draw(c: char, count: usize) -> String
```

Returns `c.to_string().repeat(count)`. Works for any `char`, including multi-byte Unicode.

```rust
use musutils::types::line::draw;

assert_eq!(draw('-', 0), "");
assert_eq!(draw('-', 5), "-----");
assert_eq!(draw('🦀', 3), "🦀🦀🦀");
```

### `line::draw_colored`

```rust
pub fn draw_colored(c: char, count: usize, color: Colors) -> String
```

Returns `color::color_str(draw(c, count), color)`. The whole repeated string is wrapped once in the color escape sequence.

```rust
use musutils::color::Colors;
use musutils::types::line::draw_colored;

let s = draw_colored('*', 3, Colors::Red);
assert_eq!(s, "\x1b[31m***\x1b[0m");
```

Empty `count` produces the reset-wrapped empty string `"\x1b[31m\x1b[0m"` — same as `color_str("", color)`.

## Limitations

- `Status` has no `Display`, no `Debug`, no equality — you cannot `println!("{:?}", Status::Ok)` and you cannot compare two values with `==`. Use `as_str()` for textual output.
- `as_colored_str` always colorizes. There is no `_auto` variant in v1; use [`types::v2`](v2.md) via `color::v2` if you need environment-aware behavior (though `Status` itself is still v1 — the coloring decision is made by `color_str`, not `color_str_auto`).
- `draw` allocates a fresh `String` each call. There is no writer-based variant.

## Differences from v2

| Aspect | v1 | v2 |
|---|---|---|
| `Status` traits | none | `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`, `Display` |
| `Status::as_plain_str` | absent | present, alias for `as_str` |
| Line helpers path | `types::line::draw` / `types::line::draw_colored` | `types::draw` / `types::draw_colored`, plus `types::line::*` |
| `deoption` | available, not deprecated | available, `#[deprecated]` |
