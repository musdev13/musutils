# color::v1

Colored terminal output, first generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["color-v1"] }
```

`color-v1` has no inter-module dependencies.

When `color-v1` is enabled, its public items are re-exported at `musutils::color::*`:

```rust
use musutils::color::{Colors, color_str};
```

## Purpose

`color::v1` provides a fixed palette of ANSI colors and a single function that wraps a string in the escape sequence for a given color, followed by a reset. It always returns the escaped string — there is no detection of whether the terminal supports color.

## `Colors`

```rust
pub enum Colors {
    Green,
    Yellow,
    Blue,
    Lime,
    Gold,
    Cyan,
    Red,
    Orange,
    Purple,
    Rose,
    Gray,
    Reset,
}
```

The variants and their escape codes:

| Variant  | `as_term_code()`      |
|----------|-----------------------|
| Green    | `"\x1b[32m"`          |
| Yellow   | `"\x1b[33m"`          |
| Blue     | `"\x1b[34m"`          |
| Lime     | `"\x1b[92m"`          |
| Gold     | `"\x1b[38;5;220m"`    |
| Cyan     | `"\x1b[36m"`          |
| Red      | `"\x1b[31m"`          |
| Orange   | `"\x1b[38;5;208m"`    |
| Purple   | `"\x1b[35m"`          |
| Rose     | `"\x1b[95m"`          |
| Gray     | `"\x1b[90m"`          |
| Reset    | `"\x1b[0m"`           |

Unlike `color::v2`, the v1 `Colors` enum does not derive `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`, or `Display`. To compare or format a color, use its `as_term_code()` string.

### `Colors::as_term_code(&self) -> &'static str`

Returns the ANSI escape sequence corresponding to the variant. `Colors::Reset` returns `"\x1b[0m"`.

```rust
use musutils::color::Colors;

assert_eq!(Colors::Red.as_term_code(), "\x1b[31m");
assert_eq!(Colors::Reset.as_term_code(), "\x1b[0m");
```

## `color_str`

```rust
pub fn color_str(text: &str, color: Colors) -> String
```

Returns `"{code}{text}\x1b[0m"` — the color's escape code, the original text, and the reset sequence.

Arguments:

- `text` — the text to color. Any `&str`, including empty and non-ASCII.
- `color` — one of the `Colors` variants. Passing `Colors::Reset` yields `"\x1b[0m{text}\x1b[0m"`.

Returns the colored string. It always ends with `"\x1b[0m"`.

```rust
use musutils::color::{Colors, color_str};

let s = color_str("hello", Colors::Cyan);
assert_eq!(s, "\x1b[36mhello\x1b[0m");
```

Empty input:

```rust
use musutils::color::{Colors, color_str};

assert_eq!(color_str("", Colors::Green), "\x1b[32m\x1b[0m");
```

Non-ASCII input is preserved verbatim:

```rust
use musutils::color::{Colors, color_str};

let s = color_str("привет 🦀", Colors::Rose);
assert!(s.contains("привет 🦀"));
assert!(s.ends_with("\x1b[0m"));
```

## Behavior notes

- `color_str` never checks `NO_COLOR`, `CLICOLOR`, `TERM`, or whether stdout is a terminal. If you need environment-aware coloring, use [`color::v2`](v2.md).
- The output string is not escaped or sanitized: any escape sequences already present in `text` pass through as-is.
- There is no function to strip color from a string in either generation.
