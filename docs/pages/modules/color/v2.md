# color::v2

Colored terminal output, second generation.

## Enable

```toml
[dependencies]
musutils = { git = "https://github.com/musdev13/musutils", features = ["color-v2"] }
```

`color-v2` has no inter-module dependencies.

When `color-v2` is enabled, its public items are re-exported at `musutils::color::*`:

```rust
use musutils::color::{Colors, color_str, color_str_auto, color_supported};
```

## Purpose

`color::v2` provides the same palette and the same unconditional `color_str` as [`color::v1`](v1.md), and adds:

- environment- and terminal-aware coloring (`color_str_auto`),
- a helper to query color support (`color_supported`),
- `Display`, `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash` on `Colors`.

## `Colors`

```rust
pub enum Colors {
    Green,
    Yellow,
    Blue,
    Lime,
    Gold,
    Cyan,
    Red,
    Orange,
    Purple,
    Rose,
    Gray,
    Reset,
}
```

Derives `Debug`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`.

Escape codes are identical to v1:

| Variant  | `as_term_code()`      |
|----------|-----------------------|
| Green    | `"\x1b[32m"`          |
| Yellow   | `"\x1b[33m"`          |
| Blue     | `"\x1b[34m"`          |
| Lime     | `"\x1b[92m"`          |
| Gold     | `"\x1b[38;5;220m"`    |
| Cyan     | `"\x1b[36m"`          |
| Red      | `"\x1b[31m"`          |
| Orange   | `"\x1b[38;5;208m"`    |
| Purple   | `"\x1b[35m"`          |
| Rose     | `"\x1b[95m"`          |
| Gray     | `"\x1b[90m"`          |
| Reset    | `"\x1b[0m"`           |

### `Colors::as_term_code(&self) -> &'static str`

Returns the ANSI escape sequence for the variant.

```rust
use musutils::color::Colors;

assert_eq!(Colors::Red.as_term_code(), "\x1b[31m");
assert_eq!(Colors::Reset.as_term_code(), "\x1b[0m");
```

### `Display` for `Colors`

`Display` writes `as_term_code()` — so `Colors::Red.to_string() == "\x1b[31m"`.

```rust
use musutils::color::Colors;

assert_eq!(Colors::Green.to_string(), Colors::Green.as_term_code());
```

### `Eq` / `Hash`

`Colors` can be used as a key in a `HashMap` / member of a `HashSet`.

```rust
use std::collections::HashSet;
use musutils::color::Colors;

let mut seen = HashSet::new();
seen.insert(Colors::Red);
seen.insert(Colors::Red);
assert_eq!(seen.len(), 1);
```

## `color_str`

```rust
pub fn color_str(text: &str, color: Colors) -> String
```

Identical semantics to [`color::v1::color_str`](v1.md#color_str): returns `"{code}{text}\x1b[0m"` and never consults the environment.

```rust
use musutils::color::{Colors, color_str};

assert_eq!(color_str("hello", Colors::Cyan), "\x1b[36mhello\x1b[0m");
```

## `color_str_auto`

```rust
pub fn color_str_auto(text: &str, color: Colors) -> String
```

Like `color_str`, but returns `text.to_string()` **without** any escape sequences when coloring should be suppressed.

Coloring is suppressed when any of the following is true:

- the `NO_COLOR` environment variable is set (any value),
- `CLICOLOR` is set to `"0"`,
- `TERM` is set to `"dumb"`,
- stdout is not a terminal (`std::io::stdout().is_terminal()` is `false`).

Otherwise the result is exactly `color_str(text, color)`.

```rust
use musutils::color::{Colors, color_str_auto};

let s = color_str_auto("done", Colors::Lime);
// When stdout is a TTY and no NO_COLOR/CLICOLOR/TERM override is present:
// s == "\x1b[92mdone\x1b[0m"
// Otherwise:
// s == "done"
```

> The `NO_COLOR`, `CLICOLOR` and `TERM` checks read the process environment. Tests that change those variables must serialize themselves — e.g. guard with a shared `Mutex`.

## `color_supported`

```rust
pub fn color_supported() -> bool
```

Returns `true` when `color_str_auto` would colorize output, i.e. none of the suppression conditions apply and stdout is a terminal.

```rust
use musutils::color::color_supported;

if color_supported() {
    // ANSI escapes are safe to emit
}
```

This function is evaluated at call time — it does **not** cache the result. Cheap enough for typical CLI usage, but do not call it in tight loops.

## Environment variables

| Variable   | Effect                                                 |
|------------|--------------------------------------------------------|
| `NO_COLOR` | Any value disables coloring.                           |
| `CLICOLOR` | Value `"0"` disables coloring; other values ignored.   |
| `TERM`     | Value `"dumb"` disables coloring.                      |

`NO_COLOR` takes precedence over the other two: the check returns `false` immediately when it is set. `CLICOLOR` and `TERM` are checked next, in that order.

## Notes

- The escape codes are the same as in v1 — this crate does not negotiate terminal capabilities or downgrade to 8/16 colors.
- `color_str` is not affected by any environment variables; only `color_str_auto` and `color_supported` are.
- Output is not sanitized: escape sequences already present in `text` pass through.
